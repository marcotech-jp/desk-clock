# Android デスククロック 設計書

## 1. 目的

Android端末を横置きのデスククロックとして使用する静的Webアプリケーションを提供する。遠距離からの時刻の読みやすさを最優先にし、天気と日付を補助情報として表示する。

## 2. 設計方針

- GitHub Pagesで配信できるHTML、CSS、Vanilla JavaScriptのみで構成する。
- 時計表示は通信や外部APIの状態に依存させない。
- 初期表示では位置情報権限を要求せず、ユーザーが「現在地を使う」を押した場合のみ取得する。
- 操作UIは小さなメニューボタンに集約し、時計の視認性を妨げない。
- APIやWake Lockが利用できない場合も時計として動作を継続する。
- ユーザー設定と直近の天気を端末内に保存する。

## 3. システム構成

| 要素 | 役割 |
| --- | --- |
| GitHub Pages | 静的ファイルのHTTPS配信 |
| Android Chrome | UI描画、時計、設定、位置情報、PWA、Wake Lock |
| Open-Meteo | 現在天気、時間別予報、日別予報を返す |
| OpenStreetMap Nominatim | 現在地座標を市区町村名へ変換する |
| GitHub Actions | 構文検証とPagesへの自動デプロイ |

ブラウザ内の時計処理と天気処理は分離する。天気APIの通信に失敗しても、端末時刻による時計更新には影響しない。

## 4. ファイル責務

| ファイル | 責務 |
| --- | --- |
| `src/index.html` | 時計、天気、メニューボタン、設定ダイアログのHTML構造 |
| `src/style.css` | 横画面中心のレイアウト、テーマ変数、設定UI |
| `src/settings.js` | テーマ・地域マスタ、位置情報と地域名の取得、保存、復元、設定変更イベント |
| `src/clock.js` | 1秒周期の時計、Wake Lock、Service Worker登録 |
| `src/weather.js` | 現在・時間別・日別天気の取得、コード変換、表示、地域別キャッシュ |
| `src/manifest.json` | PWA名、表示モード、画面方向、アイコン |
| `src/sw.js` | 同一オリジンのアプリシェルをキャッシュ |
| `.github/workflows/deploy-pages.yml` | CI検証、Pagesアーティファクト生成、デプロイ |

読み込み順は `settings.js`、`clock.js`、`weather.js` とする。`weather.js` は `settings.js` が公開する現在地域を参照する。

## 5. UI設計

### 通常画面

- 上部右: メニューボタン
- 中央: `HH:mm:ss` 形式の現在時刻
- 時計下: `M月D日 曜日` 形式の日付
- 日付下1段目: 表示地域、現在の天気記号、天気説明、現在気温
- 日付下2段目: 次の時間から2時間おき4件の天気と気温
- 日付下3段目: 今日の最高・最低気温
- 日付下4段目: 明日の天気と最高・最低気温
- 下部右: 天気取得エラーなど一時的な状態

時刻は `clamp()` とビューポート幅を利用して端末サイズへ追従する。時・分・秒・コロンをCSS Gridの固定列へ分割し、等幅数字フォントを使うことで数字が変わってもコロン位置を固定する。縦画面と低い横画面には個別のメディアクエリを適用する。

### 設定ダイアログ

ネイティブの `<dialog>` を使用する。背景クリック、閉じるボタン、Escキーで閉じられる。設定変更は保存ボタンを必要とせず即時反映する。「現在地を使う」は明示操作時だけGeolocation APIを呼び出す。

テーマはCSSカスタムプロパティで実装し、背景、前景、補助文字、アクセント、パネル、境界線を一括変更する。暗色のミッドナイトと白基調のライトを提供する。

## 6. 設定モデル

保存先は `localStorage` の `desk-clock:settings` とする。

```json
{
  "theme": "midnight",
  "locationId": "tokyo",
  "currentLocation": null
}
```

不明な値、壊れたJSON、ストレージ利用不可の場合は次の初期値を使用する。

| 設定 | 初期値 | 有効値 |
| --- | --- | --- |
| テーマ | `midnight` | `midnight`, `light` |
| 地域 | `tokyo` | `settings.js` の地域マスタに存在するID、または `current` |
| 現在地 | `null` | Geolocation APIで取得した緯度・経度、または `null` |

現在地を選択した場合、`currentLocation` は次の形式で保存する。

```json
{
  "id": "current",
  "name": "京都市",
  "latitude": 35.0116,
  "longitude": 135.7681,
  "timezone": "auto"
}
```

地域変更時は `desk-clock:location-change` カスタムイベントを発行する。天気処理はイベントを受け、進行中の古いリクエストを中断して新地域を取得する。現在地取得に失敗した場合は設定を変更せず、理由を設定ダイアログ内へ表示する。

## 7. 地域データ

固定地域は東京のみとし、必要に応じて現在地へ切り替える。

| ID | 表示名 | 緯度 | 経度 |
| --- | --- | ---: | ---: |
| `tokyo` | 東京 | 35.68 | 139.76 |

固定都市のタイムゾーンは `Asia/Tokyo` とする。現在地ではOpen-Meteoの `auto` を指定する。都市追加時は `settings.js` の `LOCATIONS` にID、表示名、緯度、経度、タイムゾーンを追加する。

現在地はGeolocation APIから得た座標を使用する。ユーザー操作ごとに1回だけNominatim Reverse APIへ問い合わせ、市区町村名を表示名として保存する。逆ジオコーディングに失敗した場合のみ「現在地」と表示する。取得済み座標と地域名を設定と一緒に保存するため、次回起動時に再度問い合わせない。座標を更新する場合は再び「現在地を使う」を押す。

## 8. 時計処理

端末の `Date` を参照し、次の秒境界までの差分を `setTimeout` へ設定する。単純な1000ミリ秒周期よりも処理遅延が累積しにくい方式とする。

タブが表示状態へ戻った際は即時更新する。時刻と日付のタイムゾーンは端末設定を使用する。

## 9. 天気処理

### リクエスト

Open-Meteo Forecast APIへ次を指定する。

- `latitude`, `longitude`: 選択地域の座標
- `current`: `temperature_2m,weather_code`
- `hourly`: `temperature_2m,weather_code`
- `daily`: `weather_code,temperature_2m_max,temperature_2m_min`
- `forecast_days`: `2`
- `forecast_hours`: `10`（現在時刻より後を2時間おきに4件表示）
- `timezone`: 固定都市は `Asia/Tokyo`、現在地は `auto`

画面表示時、地域変更時、以降30分ごとに取得する。リクエストは10秒で中断する。

時間別配列から現在時刻以前を除外し、先頭から1件おきに抽出して2時間間隔の4件を作る。表示形式は `10時 ☀ 28°` とし、画面幅を優先して降水確率などは含めない。

### キャッシュとエラー処理

天気は `desk-clock:weather:<locationId>` のキーで地域別に保存する。現在値、このあと2時間おきの4件、今日の最高・最低気温、明日の予報をまとめて保存し、通信前に保存値があれば表示して成功後に更新する。

通信失敗時は保存値を継続表示し、保存値もない場合は `--°C` とエラーメッセージを表示する。APIの天気コードは画面へ直接出さず、晴れ、曇り、霧、雨、雪、雷雨などの表示へ変換する。

## 10. Wake Lock

表示中に `navigator.wakeLock.request("screen")` を要求する。非対応、拒否、取得失敗は握りつぶして時計動作を継続する。

タブ非表示などでロックが解除された場合、表示状態へ戻ったタイミングで再取得する。ページ離脱時は保持中のロックを解放する。

## 11. PWAとオフライン方針

マニフェストは `standalone` と `landscape` を指定する。Service WorkerはHTML、CSS、JavaScript、マニフェスト、アイコンをアプリシェルとしてキャッシュする。

同一オリジンのGETリクエストはキャッシュを優先し、バックグラウンドで最新版へ更新する。Open-Meteoは別オリジンのためService Workerでは扱わず、`weather.js` の地域別キャッシュでフォールバックする。

アプリシェルの互換性を壊す変更時は `sw.js` の `CACHE_NAME` を更新し、古いキャッシュをactivate処理で削除する。

## 12. CI/CD

`main` ブランチへのpushまたは手動実行でワークフローを開始する。

1. リポジトリをチェックアウトする。
2. `src` 内のJavaScriptを `node --check` で構文検証する。
3. `src/manifest.json` をJSONとして検証する。
4. `src` 内の必須ファイルの存在を検証する。
5. `src` だけをPagesアーティファクトへアップロードする。
6. GitHub Pagesへデプロイする。

デプロイには `pages: write` と `id-token: write` の最小権限を使用する。同時デプロイはconcurrencyグループで直列化する。

## 13. セキュリティとプライバシー

- Geolocation APIはユーザーが設定画面のボタンを押した場合のみ呼び出す。
- 取得した座標と逆ジオコーディング結果は端末内へ保存する。
- 現在地の座標は天気取得のためOpen-Meteoへ、地域名取得のためNominatimへ送信する。
- Nominatimはユーザー操作時のみ1回呼び出し、結果を再利用して利用上限へ配慮する。
- 地域名データのOpenStreetMap帰属表示を設定画面に常時表示する。
- APIキーや認証情報をソースへ持たない。
- 外部スクリプト、Webフォント、解析タグを読み込まない。
- GitHub PagesのHTTPS上でPWAとWake Lockを利用する。

## 14. 確認項目

- 横画面で時刻が欠けず、天気・日付より大きく表示される。
- 縦画面や高さの低い端末でも表示が重ならない。
- 秒表示が秒境界に追従する。
- 数字の組み合わせが変わっても2つのコロン位置が動かない。
- 2テーマが即時反映され、再読み込み後も維持される。
- 東京と現在地を切り替えられ、地域名と天気が更新される。
- 現在地取得の許可、拒否、タイムアウトを処理できる。
- 現在地取得後に市区町村名が表示され、逆ジオコーディング失敗時はフォールバックできる。
- 今日と明日の最高・最低気温、明日の天気が表示される。
- 現在時刻より後の天気と気温が2時間おきに4件表示される。
- 天気通信失敗時も時計が動き続ける。
- ダイアログをタッチ、キーボードの両方で操作できる。
- ホーム画面追加後にstandalone・landscapeで起動する。
- タブ復帰後にWake Lockを再取得する。
